You are the lead research engineer and software architect responsible for implementing a complete research-grade AI model steganalysis/security scanner.

This is NOT a toy project, demo-only prototype, or collection of unrelated scripts.

The system must implement the research methods described below, integrate them into one coherent multi-evidence model-steganalysis pipeline, generate controlled evaluation datasets, run reproducible experiments, and expose the analysis through a professional application architecture.

============================================================
1. PROJECT OBJECTIVE
============================================================

Build a model-security scanner that analyzes neural-network model artifacts for hidden steganographic/malicious modifications.

Core research hypothesis:

Complementary evidence sources can provide more robust detection of heterogeneous model-steganography mechanisms than relying on a single signal.

The system must therefore combine:

1. Weight-space / bit-level evidence
2. Paper-derived Trojan Signature evidence
3. Structural/topological evidence
4. Optional behavioral/implicit-feature evidence
5. Matched clean-reference deviation
6. Controlled attack/evaluation evidence
7. Multi-evidence fusion
8. Explainable model-level and layer-level risk assessment

The scanner should produce a machine-readable and human-readable security report.

IMPORTANT:
Do not invent research algorithms where a paper/repository already specifies the algorithm.
Do not replace a paper-derived method with a generic heuristic and call it the same method.
Clearly distinguish:
- research-derived algorithms
- repository-derived implementations
- engineering adaptations
- our system-level integration/fusion

------------------------------------------------------------
PAPER 2 — TROJAN SIGNATURES
------------------------------------------------------------

Implement the actual paper mechanism:

final classification layer
    ↓
class-row average weights
    ↓
identify largest row
    ↓
Dixon Q statistic
    ↓
critical-value based statistical decision

Formula:

For class row i:

w_i = (1/d) * Σ_j W_i,j

After sorting:

w_i1 <= ... <= w_ic

Q = |w_ic - w_i(c-1)| / (w_ic - w_i1)

Implement:

- row means
- candidate target class
- Q statistic
- correct Dixon critical values
- significance/configuration
- evidence reporting
- layer attribution

Do NOT use the paper's published example threshold as a universal threshold.

Also implement the adaptive attacker formulation for controlled robustness evaluation:

L_reg = L_CE + γ [ E[W_t] - E[W] ]

This is an attack/evasion evaluation module, not the detector.

Track:
- Q suppression
- clean accuracy
- trigger efficacy/ASR
- changes in the target-row distribution

------------------------------------------------------------
PAPER 3 — IMPLICIT FEATURES
------------------------------------------------------------

Implement the paper's black-box behavioral steganalysis method.

Core process:

fixed probe image sequence
    ↓
candidate model inference
    ↓
softmax output vectors
    ↓
implicit feature matrix D_k
    ↓
paper-compatible preprocessing
    ↓
steganalysis network
    ↓
plain/secret probability

For a g-class classifier:

F_i ∈ R^g

D_k = {F_k1, ..., F_kN}

The paper's main experimental representation uses:

N = 1000
D_k = 1000 × g

For 10-class experiments:

1000 × 10

The paper compares:
- 100 × 100 reshaping
- 1000 × 10 representation

The paper-selected approach is the longer 1000 × 10 representation.

Implement a configurable detector based on the paper's model-06-long design.

Include:
- convolutional feature extraction
- residual blocks
- global average pooling
- fully connected output
- sigmoid probability

Use binary cross entropy and Adam.

Expose configuration for:
- N
- probe dataset
- model families
- training dataset
- number of training models
- batch size
- epochs
- learning rate

This is an OPTIONAL behavioral branch.

If executable inference is unavailable, scanner must continue with static evidence.

The paper's limitations must be documented:
- large model dataset required for training
- fixed-image selection lacks a quantitative universal criterion
- designed/tested for classification networks
- training cost

PAPER 4 — DISARMING ATTACKS
------------------------------------------------------------

Use this paper primarily to implement controlled LSB attack generators.

Implement:

FMLA
    Full Mantissa LSB Attack
    23 mantissa bits

HMLA
    Half Mantissa LSB Attack
    12 low-order mantissa bits

HBLA
    Half Byte LSB Attack
    4 low-order mantissa bits

The attack implementation must:

- operate on FP32 IEEE-754 representation
- manipulate raw bits correctly
- preserve sign/exponent unless the attack definition says otherwise
- record exact affected bits
- record affected tensors/layers
- record payload size
- record embedding rate
- record affected parameter count
- validate resulting model integrity

Use synthetic benign payload data for experiments.

Evaluate:

clean model
vs.
HBLA
vs.
HMLA
vs.
FMLA

Track:
- model accuracy before/after
- changed parameter count
- numerical perturbation
- bit-level perturbation
- detector evidence

Do NOT make the paper's CDR/sanitization algorithms a mandatory Phase-1 component.

Treat:
- FLP
- K-LRBP
- quantization

as future mitigation/sanitization extensions unless explicitly required by the evaluation plan.
